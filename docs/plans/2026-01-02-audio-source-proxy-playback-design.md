# 多源音频代理播放设计

- 日期：2026-01-02
- 状态：Draft
- 负责人：TBD

## 背景
当前多源音频链路无法稳定获取真实音频，主要问题包括：前端播放页依赖 `episodes` 字段但后端返回 `chapters`；后端缺少章节列表接口导致播放页无章节；音频 URL 解析在部分平台不稳定；前端未统一代理播放，容易被源站拦截或因 HTTP 直链播放失败。

## 目标
- 打通端到端播放闭环：搜索 → 播放页 → 任意章节可播放。
- 覆盖喜马拉雅、酷我、幻听三大已接入音源。
- 统一代理入口并启用严格白名单，提升音频获取稳定性。
- 后端返回 `audio_url` 与 `audio_proxy_url`，前端优先代理，失败回退直链。

## 非目标
- 不新增音源、不引入登录态或付费内容。
- 不做复杂反爬、代理池或 TLS 指纹伪装。
- 不改动数据库结构或做数据迁移。

## 方案概要
- 后端补齐章节接口，书籍详情返回 `chapters`，兼容前端字段映射。
- 新增统一代理接口 `/api/v1/proxy/audio`，仅允许三大音源白名单域名与路径。
- `GetSourceAudio` 返回原始音频 URL 与代理 URL。
- 前端播放优先使用代理，失败自动回退原始直链。
- 各音源补齐最小解析兼容（喜马拉雅 data/playUrlInfo 兼容、幻听 m3u8/脚本解析补偿、酷我直链代理化）。

## 架构与数据流
- 播放页先调用 `/sources/:id/books/:bookId` 获取详情与章节。
- 点击章节后调用 `/sources/:id/audio/:episodeId` 获取 `audio_url` 与 `audio_proxy_url`。
- 播放器先尝试 `audio_proxy_url`，失败回退 `audio_url`。
- 代理服务校验白名单后流式转发音频，支持 Range 请求。

## 错误处理与降级
- 代理失败自动回退直链播放。
- 解析失败返回明确错误，前端提示并支持重试或换集。
- 代理拒绝非白名单 URL，返回 400/403。

## 安全与合规
- 严格白名单、禁止私网与非 http/https。
- 仅公开免费内容，日志避免记录完整音频 URL。

## 测试与验证
- 三平台各选一本书，首集可播放。
- 代理接口对合法/非法 URL 的行为正确。

## 发布与回滚
- 无数据库变更，灰度可选。
- 出现问题可回退到原始直链播放逻辑。
