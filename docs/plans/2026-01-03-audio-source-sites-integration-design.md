# 听书网站音源接入设计

- 日期：2026-01-03
- 状态：Draft
- 负责人：TBD

## 背景
现有项目已支持喜马拉雅/酷我/幻听三大音源，但移动端搜索仍以单平台为主，覆盖不足。`docs/听书网站爬取技术指南.md` 识别出 5 个可爬取站点，需要以现有 Source 接口的方式接入，并保持最小改动与可维护性。

## 目标
- 接入 5 个站点（书音FM、七八听书网、听书迷、乐听吧、猫耳FM），每个站点完整支持搜索/详情/章节/播放。
- 移动端默认全局搜索并按音源分组展示，每组显示 5 条并提供“查看更多”进入单源分页。
- 仅抓取公开免登录内容；站点失败时自动降级/禁用，避免影响全局体验。
- 音频代理按需配置：仅对确实需要防盗链的站点启用白名单。

## 非目标
- 不实现离线爬虫入库或定时任务。
- 不处理登录/付费内容、不绕过反爬。
- 不引入通用抓取框架或大规模重构移动端 UI。

## 方案概要
- 后端为每个站点新增独立 Source 实现，基于 goquery 解析 HTML 或公开接口。
- Source Manager 注册新源并纳入全局搜索与健康检查。
- 音频代理仅在验证需要时纳入白名单，保持中转成本可控。
- 移动端搜索页新增“全部/单源”选择入口，按音源分组渲染结果。

## 架构与数据流
- 全局搜索：移动端 → `/api/v1/global/search?q=...` → Source Manager 并发 Search → 返回结果 → 移动端按 `source_id` 分组。
- 单源搜索：移动端 → `/api/v1/sources/:id/search` → 分页结果。
- 播放链路：移动端 → `/api/v1/sources/:id/books/:bookId` → `/api/v1/sources/:id/audio/:episodeId` → `audio_url`/`audio_proxy_url`。

## 错误处理与降级
- 搜索/解析失败记录失败率，触发自动禁用机制。
- 前端对失败源显示提示并允许切换其他音源。

## 安全与合规
- 仅公开免登录内容，遵守 robots.txt 与请求频率控制。
- 代理白名单限制域名与协议，禁止私网地址。

## 测试与验证
- 后端：每站点至少验证一次搜索、详情、章节、播放。
- 前端：全局搜索分组展示与单源分页切换可用。

## 发布与回滚
- 无数据库变更，按需灰度发布。
- 发现问题可通过 `/sources/:id/disable` 快速禁用单源。

## 风险与缓解
- 站点结构变更导致解析失败：通过监控降级 + 快速修复。
- 访问受限（如 Cloudflare）：失败源自动禁用，用户可切换其他源。

## Open Questions
- 各站点是否需要代理白名单与 Referer/UA，需上线前验证确认。
